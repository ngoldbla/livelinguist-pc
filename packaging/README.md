# Packaging (Windows 11 x64 only)

v1 ships a **per-user NSIS installer** and a **portable ZIP**, built and
published by `.github/workflows/release.yml`. Unsigned until SignPath
Foundation signing is set up (ADR 0020); see ADR 0023 for the public release
path.

## Release (automatic)

1. Set `[workspace.package] version` in `Cargo.toml` (for example `1.0.0`).
2. Merge to `main`, then tag and push: `git tag v1.0.0 && git push origin v1.0.0`.
3. CI builds on `windows-latest`, self-tests the payload, installs it silently,
   self-tests the installed app, upgrades, uninstalls, self-tests the portable
   ZIP, attests provenance (public repo), and publishes the GitHub release with
   `SHA256SUMS.txt` and the notes from `packaging/release-notes.md`.

A tag with a suffix (`v1.0.0-rc.1`) publishes a **pre-release**, which the
"latest release" link skips. "Run workflow" on the Actions tab is a dry run:
the same build and tests, with files kept as a workflow artifact and no release.
The tag must equal `v` + the Cargo version or the run fails.

## Build locally (on Windows)

```powershell
pwsh scripts/build-windows.ps1            # needs Rust (MSVC), Bun 1.4.5, NSIS
pwsh scripts/test-installer.ps1 -Version 0.1.0
```

Output in `dist/`: `LiveLinguist-<ver>-setup.exe`,
`LiveLinguist-<ver>-portable.zip`, `SHA256SUMS.txt`, and the payload in
`dist/windows/`.

## Layout (ADR 0021)

`dist/windows/`, installed to `%LOCALAPPDATA%\Programs\LiveLinguist`:

- `livelinguist.exe`: Bun-compiled GPUIX UI (no console window, app icon)
- `gpuix-native.win32-x64-msvc.node`: GPUIX renderer addon
- `livelinguist-core.node`: Rust core (capture, sherpa-onnx, llama.cpp; static CRT)
- `licenses/`: `LICENSE.txt`, `NOTICE.txt`, `THIRD_PARTY.md`

Packs and UI locales are embedded. Models are **not bundled**; they download
to `%LOCALAPPDATA%\LiveLinguist\models`, which uninstall keeps unless the user
ticks "Also delete downloaded language models".

`livelinguist.exe --self-test[=report.json]` loads both addons without opening
a window and exits 0 or 1. A packaged build whose core addon fails to load shows
a "could not start" screen; it never falls back to the demo transport.

## Installer behaviour (`nsis/livelinguist.nsi`)

- No admin (`RequestExecutionLevel user`), HKCU registration only.
- Welcome → Install → Finish with "Start Live Linguist now" (checked). No folder page.
- Blocks Windows 10 and ARM64 with a plain message.
- Upgrades close a running copy first (asks; silent installs close it).
- Removes only the files it installed, never the whole folder.
- Start menu and desktop shortcuts; Installed apps entry with icon, version and size.

The icon is generated by `scripts/make-icon.py` (`packaging/icons/livelinguist.ico`).
