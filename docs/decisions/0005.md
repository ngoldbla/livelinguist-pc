# 0005 — Core implementation language: Rust

- Status: accepted
- Date: 2026-11-21
- Decision IDs: D-002
- Master plan: `docs/plans/2026-11-21-live-linguist-pc-master-plan.md`

## Context

Audio/ML glue, deterministic text logic, and a TypeScript UI need a single in-process core.

## Options

Rust gives safe FFI to llama.cpp/sherpa-onnx, a strong test story, and a napi-rs bridge. C++ has easier direct library calls but weaker safety/testing. Swift on Linux lacks the ML and desktop ecosystem.

## Decision

Implement the core in Rust as a workspace; expose a transport-neutral protocol and a thin napi shell. Do not use UniFFI.

## Consequences

Easy: one core for Windows and Linux, tests as spec. Hard: C++ build dependencies. Revisit only if a required library has no usable Rust binding.

## Evidence

`core/Cargo.toml`; `core/crates/ll-protocol`.
