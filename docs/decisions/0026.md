# 0026 - Quiet utility UI, one decision per screen, kept preferences

- Status: accepted
- Date: 2026-11-25
- Decision IDs: D-063
- Related: 0007 (GPUIX + React), 0018 (v1.0 single-screen scope), 0021
  (packaging); `docs/plans/2026-11-22-v1-scope.md` section 4.
- Evidence: `docs/qa/2026-11-25-ui-clarity.md`,
  `docs/screenshots/m2-windows/`

## Context

The first complete UI passed its a11y counts and contrast tests but failed a
design review (`docs/qa/2026-11-25-ui-clarity.md`): 30-40% of most windows was
empty, the console presented ten competing signals, two toggles were inert,
language status was repeated three times, the overlay ignored the caption-size
setting, preferences reset on every launch, the current window mode was not
shown, and metadata was set in 9-11px type named after the implementation
("Tier 1", "ASR status", "English reversion"). The product is for people who
need easier language, so the chrome contradicted the audience.

The macOS product this ports was not available in this repository; the flow was
simplified from the documented v1.0 journey (choose language, choose sound,
start, read, export) and the existing screens.

## Options

1. **Polish the Aurora glass system in place.** Keep the three-column console,
   the layered glass, and the gradients; only tune spacing and copy. Cheapest,
   but leaves the hierarchy and the empty canvas.
2. **Quiet utility system, one decision per screen (chosen).** Flat near-black
   surfaces, one accent, no decorative gradients or shadows, one type scale with
   a 12px floor, a single-column console (language -> sound -> start), settings
   as one form, the overlay honoring caption size and the tier choice, and
   preferences persisted to disk.
3. Full redesign with a new visual world. More risk than the task needs; the
   transcript itself already worked.

## Decision

Option 2.

- **Palette.** Near-black fields (`#070709`/`#0A0A0D`), flat surfaces
  (`#111116`), one violet accent (`#AFA2FF` text, `#6B58E0` primary fill), and
  mint/amber/rose for state only. No glass blur (GPUIX has none), no drop
  shadows on controls, and only two very low-alpha background washes that
  `Reduced effects` turns off.
- **Type.** One family (Segoe UI on Windows, Noto Sans elsewhere), six sizes
  (12/13/14/20/28/34), nothing below 12px. Section titles no longer outrank
  page titles.
- **Flow.** Onboarding stays three beats but is one card with one primary action;
  the console is language, sound, start, two options, and a footer with model
  state, privacy and licenses; the live screen keeps the transcript as the
  spine and moves session counts into one line; settings is one form with an
  inline preview; summary leads with "Start another session".
- **State.** `UiSettings` lives in `ui/src/settings.ts`, is read at boot and
  written on every change to `%LOCALAPPDATA%\LiveLinguist\ui-settings.json`
  (XDG on Linux). Console toggles write the same settings as Settings. The
  window-mode control shows the active mode. The overlay reads `captionSize` and
  `showTier1`. Opening Settings from the 780x250 overlay first restores the
  console window.
- **Words.** English display values were rewritten for the jargon keys (keys
  stay stable, so existing translations keep resolving), and 18 new keys were
  added to all 29 catalogs. `statusLabel` now says "Live captions" /
  "Simplified text only".
- **Windows.** Onboarding 980x680, console 1100x700, settings 1000x860, summary
  1180x820, licenses 1020x820, expanded 1180x900, overlay 780x250.

## Consequences

Easy: the first screen fits without empty panels, the primary action is one
click after the defaults, preferences survive a restart, the overlay is readable
during a call, and the words match the audience.

Hard: 18 strings ship in English in 28 catalogs until the translation pass
lands. The independent UI-locale picker is still missing; the "follow learning
language" toggle remains the only control. The Windows build relies on the
system Segoe UI face rather than a bundled Noto Sans, which is a packaging task.
The GPU test renderer captures a fixed 1536x1061 canvas, so the production window
sizes are asserted by `windowSize.test.ts`, not by the screenshots.

## What would overturn it

- Users asking for a light theme or a more expressive brand surface: add a theme
  layer rather than reintroducing gradients into this one.
- A UI-locale picker or per-surface settings: extend `UiSettings` and the
  settings form, keeping one write path.
- Translation review finding the rewritten English values unusable for a
  catalog: update that catalog's value under the same key.
