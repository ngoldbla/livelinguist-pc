# 0012 — Event delivery and envelope

- Status: baseline
- Date: 2026-11-21
- Decision IDs: D-033/D-038
- Master plan: `docs/plans/2026-11-21-live-linguist-pc-master-plan.md`

## Context

The UI must not miss or reorder events, and a late attach must not duplicate state. GPUI's main loop may starve TSFN callbacks.

## Options

A monotonic envelope `{v, seq, ts, event}` plus `getSnapshot() -> {state, lastSeq}` lets the UI drop stale events. TSFN is the primary delivery path; a GPUIX frame/tick pump is the fallback if p99 stalls.

## Decision

All core events are enveloped and applied monotonically. The bridge delivers through TSFN; the event-delivery harness runs 100 events/s for 10 minutes under Bun and Node and records p50/p99. If stalled, pump from the frame tick.

## Consequences

Easy: deterministic UI state. Hard: every event producer must respect the sequence. Revisit if the harness cannot meet the 50 ms p99 target.

## Evidence

`core/crates/ll-protocol`; `core/crates/ll-bridge`; `docs/qa/2026-11-21-event-delivery.md`.


## Addendum 2026-11-21 — measured delivery

`deliveryTest(100, 600)` ran concurrently under Node 22.23.1 and Bun 1.4.5
against the napi TSFN. Both received 60,000/60,000 events with zero drops:
Node p50 0.59 ms / p99 1.07 ms; Bun p50 1.45 ms / p99 1.94 ms (threshold 50 ms).
The GPUIX frame/tick pump remains a documented fallback, not needed here.
