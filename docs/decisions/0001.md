# 0001 — ASR runtime: sherpa-onnx

- Status: accepted
- Date: 2026-11-21
- Decision IDs: D-012
- Master plan: `docs/plans/2026-11-21-live-linguist-pc-master-plan.md`

## Context

The port needs streaming ASR on x86-64 Windows/Linux, CPU-only in v1, with endpointing and per-locale model selection. The Mac reference used CoreML/ANE, which has no x86 equivalent.

## Options

sherpa-onnx 2.0.2 exposes `OnlineRecognizer` and streaming transducers with endpoint rules, ships a Rust crate, and is already the runtime assumed by the Windows PRD. whisper.cpp is pseudo-streaming (worse word-to-glass); ONNX Runtime alone means reimplementing the recognizer loop and endpointing.

## Decision

Use `sherpa-onnx` on CPU for v1. Per-locale `ok`/`degraded`/`simplify_only` status is data from the S-3A WER matrix. The Nemotron ONNX export is the first candidate; per-language streaming zipformer models are the fallback.

## Consequences

Easy: one recognizer loop, CPU everywhere, endpointing owned by sherpa. Hard: the Nemotron export must load and the license must permit redistribution. Impossible: GPU ASR in v1. Revisit if RTF on tier C exceeds 0.6 or coverage falls below the matrix.

## Evidence

`docs/qa/2026-11-21-version-verification.md`; `core/crates/ll-asr`; S-3A results are recorded in `docs/qa/2026-11-21-asr-coverage.md`.

## Addendum 2026-11-22

The model is one NVIDIA Nemotron 3.5 streaming 0.6B int8 package at 560 ms for
all 29 locales; sherpa-onnx publishes the ONNX files, so there is no export step
and no per-language fallback in 1.0. See ADR 0019 and
`docs/qa/2026-11-22-model-pins.md`.

## Addendum 2026-11-24 — wired (T11–T14)

`sherpa-onnx` 2.0.1 (static CPU libs) runs the pinned model through
`ll_asr::SherpaAsr`. Two pipeline rules follow from "endpointing owned by
sherpa":

- A self-endpointing engine (`AsrEngine::needs_continuous_audio`) gets every
  chunk. The energy VAD (RMS ≥ 0.01) no longer gates it: a quiet FLEURS clip
  (peak frame RMS 0.012) lost most of its speech behind that gate.
- Pauses for such an engine come from its endpoint
  (`AsrEngine::take_endpoint`), not the energy VAD. The segmenter finalizes
  the utterance before the engine's fresh hypothesis arrives, so no text is
  dropped. Before this change, quiet speech was split per chunk and repeated.
  Mock engines keep the VAD gate and VAD pauses.

Language conditioning for this streaming transducer was not found in
sherpa-onnx 2.0.1 (T12). The model gets no language hint.
