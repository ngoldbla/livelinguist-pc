# 0021 - Packaging the GPUIX native addon (single exe does not start)

- Status: accepted (owner decision, 2026-11-24)
- Date: 2026-11-24
- Decision IDs: D-058
- Related: 0015 (Windows-only v1), 0020 (code signing), task T37

## Context

Owner Windows test, 2026-11-24 (`docs/qa/2026-11-24-windows-feedback.md`):
the `bun build --compile` exe from `scripts/build-windows.ps1` does not start.
Two native addons are loaded at runtime, and neither is reachable from inside
a compiled Bun executable:

- `@gpuix/native` picks its binary with a dynamic
  `require('@gpuix/native-win32-x64-msvc')` (napi-rs loader), which
  `bun build --compile` cannot embed;
- `ui/src/bridge/transport.ts` loads `../../livelinguist-core.node` relative to
  the module, which inside the exe points into Bun's virtual file system.

The napi-rs loader in `@gpuix/native@0.11.0` (`index.js`) honours
`NAPI_RS_NATIVE_LIBRARY_PATH` before any package lookup.

## Options

1. **Compiled exe + addons beside it (recommended).** Keep `livelinguist.exe`
   from `bun build --compile`. Ship `gpuix-native.win32-x64-msvc.node` and
   `livelinguist-core.node` next to it. A small entry module sets
   `NAPI_RS_NATIVE_LIBRARY_PATH` to `<exe dir>\gpuix-native.win32-x64-msvc.node`
   and then dynamically imports the app (static imports are hoisted, so the
   variable must be set before `@gpuix/*` is first imported); `transport.ts`
   resolves the core addon from `dirname(process.execPath)` when compiled.
   One exe to launch, two `.node` files in the install folder; NSIS and the
   portable ZIP already ship a folder.
2. **Bun runtime + bundled JS.** Ship a pinned `bun.exe`, a `bun build` bundle,
   and `node_modules/@gpuix/native-win32-x64-msvc`; start through a shortcut
   or launcher. More files, a visible runtime, and a launcher to sign.
3. **Wait for upstream.** Ask GPUIX for a statically embeddable addon. Blocks
   T37 on a third party.

A true single-file exe is not possible with either addon as it stands; the
installer and the portable ZIP are folders anyway (README "Layout").

## Decision

Accepted 2026-11-24 by the owner after the Windows retest
(`docs/qa/2026-11-24-windows-retest.md`): **option 1**. Keep `livelinguist.exe`
from `bun build --compile` and ship `gpuix-native.win32-x64-msvc.node` and
`livelinguist-core.node` beside it; the entry module sets
`NAPI_RS_NATIVE_LIBRARY_PATH` to `<exe dir>\gpuix-native.win32-x64-msvc.node`
before `@gpuix/*` is first imported, and `transport.ts` resolves the core addon
from `dirname(process.execPath)` when compiled. The core addon must never fall
back to the mock transport silently when it fails to load in a packaged build
(golden rule 7 applies to the shipped app too); a load failure should be an
error screen.

## Consequences (option 1)

- `scripts/build-windows.ps1` copies the GPUIX `.node` from `ui/node_modules`
  into `dist/windows/` (implemented 2026-11-25 with `src/packaged.ts`; the
  unused `packaging/packager.json` was removed, NSIS is the only installer).
- Both `.node` files are signed with the exe (ADR 0020).
- Windows acceptance: launch the installed exe and the unzipped portable
  build on a clean Windows 11 machine.
