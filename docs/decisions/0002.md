# 0002 — Simplifier runtime: llama.cpp GGUF

- Status: accepted
- Date: 2026-11-21
- Decision IDs: D-011
- Master plan: `docs/plans/2026-11-21-live-linguist-pc-master-plan.md`

## Context

One quantized model must run on CPU, Vulkan, and optional CUDA on Windows, and on Linux dev. The Mac used MLX, which does not exist on x86.

## Options

llama.cpp via `llama-cpp-2` supports GGUF Q4_K_M across CPU/Vulkan/CUDA and has mature Qwen3 chat-template handling. ONNX Runtime GenAI has weaker 4-bit LLM maturity; Candle/mistral.rs lack Vulkan.

## Decision

Use `llama-cpp-2` 0.1.161 with `dynamic-backends`; CPU is the baseline, Vulkan is universal GPU, CUDA is an optional pack. Qwen3 0.6B Q4_K_M is primary and 1.7B is escalation.

## Consequences

Easy: one model format and backend loader for both OSes. Hard: C++ build and dynamic backend packaging. Impossible: a runtime without C++ native libs. Revisit on a quality gate failure if Q8_0 is required.
