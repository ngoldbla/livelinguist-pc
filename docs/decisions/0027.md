# 0027 - Custom title bar for the frameless window

- Status: accepted
- Date: 2026-11-25
- Decision IDs: D-064
- Related: 0008 (window modes and overlay policy), 0021 (packaging), 0026
  (quiet utility UI)
- Evidence: `docs/qa/2026-11-25-ui-clarity.md`,
  `docs/screenshots/m2-windows/console.png`

## Context

GPUIX creates the app window with `titlebarTransparent: true`, so the OS caption
is not drawn and the app draws its own chrome. The overlay had a Move control,
but the console, onboarding, settings, summary and expanded screens had no drag
region, no minimize, no maximize and no close. Users could not move the window
and could only quit with Alt+F4 or the taskbar.

The window is a single frameless surface that morphs between console, overlay
and expanded. Restoring the native title bar for every mode would put a caption
on the 780x250 caption overlay, which must stay borderless. Toggling Win32 frame
styles per mode is possible but needs client-area and frame-refresh surgery in
the Rust window policy.

## Options

1. **Native title bar everywhere.** One flag change; the overlay gains a Windows
   caption and loses its floating-panel look.
2. **Custom title bar outside overlay mode (chosen).** Draw a 34px bar in the
   app, drag it through the existing native move helper, minimize/zoom through
   the GPUIX renderer, and close through a new bridge command that posts
   `WM_CLOSE`. The overlay keeps its Move control and stays frameless.
3. Per-mode Win32 caption add/remove. Most native, most risk: frame changes
   move the client area, and the app's window-size math assumes the current
   client-only size.

## Decision

Option 2.

- `WindowChrome` renders above every screen except the overlay: twin-L at 18,
  the product name, a drag region, and 44x34 minimize / maximize-or-restore /
  close buttons (Lucide minus, square, x). Double-clicking the drag region
  toggles maximize.
- Drag calls the existing `beginDrag` bridge command. `ll-window` now moves
  with `HWND_TOP` instead of `HWND_TOPMOST`, so dragging the console no longer
  leaves it permanently always-on-top; the overlay is topmost by policy.
- Minimize and maximize use GPUIX `minimizeWindow()` and `zoomWindow()`.
- Close calls a new `closeWindow` bridge command; `ll-window::close_current_window`
  posts `WM_CLOSE` to the app window, the same path as the native close button.
  If the addon is older and lacks the method, the UI exits the process.
- The overlay keeps its own Move button and gains no chrome.

## Consequences

Easy: the window can be moved, minimized, maximized and closed from the UI on
Windows, while the overlay remains a floating caption panel. No native frame
returns, so the dark surface stays unbroken.

Hard: a custom caption does not get Windows 11 Snap Layouts on hover or the
Alt+Space system menu (Win+arrows still snap), and needs a human pass for drag,
double-click and the three buttons. On Linux dev close falls back to process
exit and the move helper is a no-op, so the chrome is only fully exercised on
Windows. A stale native addon (before `close_window`) also falls back to exit.

## What would overturn it

- GPUIX exposes per-mode native decorations or a native window-controls API:
  use that and delete the custom bar.
- Snap Layouts or the system menu become requirements: restore the native
  title bar and accept caption chrome on the overlay (or make the overlay a
  second window, post-1.0).
