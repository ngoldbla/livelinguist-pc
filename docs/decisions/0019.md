# 0019 - 1.0 model set: Nemotron 3.5 ASR (560 ms) and Qwen3 0.6B EasyLanguage

- Status: accepted
- Date: 2026-11-22
- Decision IDs: D-056
- Related: 0001 (ASR runtime), 0002 (simplifier runtime), 0018 (v1.0 scope)
- Evidence: `docs/qa/2026-11-22-model-pins.md`

## Context

The v1.0 plan named `ndgold/nemotron-3.5-asr-streaming-0.6b-onnx` as the ASR
artifact and left two things open: whether that export was reachable, and
whether per-language fallback models would be needed for the 29 locales. The
repository then recorded the artifact as unreachable and carried per-language
zipformer/Vosk candidates, a 1.7B LLM escalation, and unresolved model licenses.

The macOS/iOS product uses NVIDIA Nemotron 3.5 streaming ASR. The model is public
on Hugging Face (`nvidia/nemotron-3.5-asr-streaming-0.6b`): 600M parameters,
cache-aware FastConformer-RNNT, language-ID prompt conditioning, 40 locales, of
which 32 transcribe out of the box. All 29 FrameworkPack languages are inside
that set. `sherpa-onnx` — the runtime already chosen in ADR 0001 — publishes
pre-exported int8 packages for 80/160/320/560/1120 ms chunks, so no ONNX export
task is required. The simplifier's GGUF already exists publicly
(`ndgold/Qwen3-0.6B-EasyLanguage-GGUF`, Apache-2.0).

## Options

1. Keep the per-language model zoo (streaming zipformer/Vosk per locale).
2. One Nemotron 3.5 int8 model at 560 ms for every locale, mirrored per file.
3. One Nemotron 3.5 int8 model at 1120 ms (higher accuracy, more delay).
4. Ship the sherpa `.tar.bz2` as-is and add archive extraction to `ll-models`.

## Decision

Option 2.

- **Speech to text:** `sherpa-onnx-nemotron-3.5-asr-streaming-0.6b-560ms-int8-2026-06-11`,
  unpacked and mirrored as four files (`encoder.int8.onnx`,
  `decoder.int8.onnx`, `joiner.int8.onnx`, `tokens.txt`) in the public
  `ndgold/nemotron-3.5-asr-streaming-0.6b-onnx` repository, at commit
  `f73e3bc81614fa69e24b091b892e8672983fbb9c`. Per-file SHA-256 and sizes are
  committed in `ModelCatalog::plan_default()`. The upstream sherpa asset ID and
  archive digest are recorded as provenance.
- **Simplification:** `ndgold/Qwen3-0.6B-EasyLanguage-GGUF` at revision
  `658db5ad6a05e3f549990b10e8d8c59a78866695`,
  `Qwen3-0.6B-EasyLanguage-Q4_K_M.gguf`, 396,704,608 bytes, Apache-2.0.
- **One of each.** No per-locale ASR models, no Vosk/zipformer fallback, no
  1.7B in 1.0, no bundled VAD model (the energy VAD stays).
- **Chunk size 560 ms** for all tiers. The published averages are 10.38 / 10.00
  / 9.49 / 9.12 / 8.84% WER for 80 / 160 / 320 / 560 / 1120 ms: 560 is the knee.
  Cache-aware chunking is non-overlapping, so chunk size does not rescue RTF;
  it trades latency for accuracy. 160 ms is measured once on tier C and only
  adopted if 560 misses the latency gate.
- **First-run download,** not bundling: ~682 MB ASR plus ~397 MB LLM (~1.08 GB).
  Resumable per file, SHA-256 verified before use, disk preflight, under
  `%LOCALAPPDATA%\LiveLinguist\models`.
- **Mirror, not tarball.** The existing downloader already does per-file resume
  and hash verification; a mirror needs no new code, no `tar`/`bzip2`
  dependency, and no double-disk extraction. The mirror is public at commit
  `f73e3bc8…`; a tampered mirror fails the hash check instead of installing
  different weights.
- **Language conditioning is explicit.** Pass the two-letter sherpa language key
  derived from `Language` (for example `ar`, `pt`, `zh`), not the product locale
  string and not `auto`. Auto-detect is a dev-only scenario so captions cannot
  flip languages or leak tag markers.

## Consequences

Easy: one ASR model covers every locale the app ships; no export pipeline, no
model zoo, no per-language downloads; PC and iOS share the same weights; the
catalog is fully pinned so a changed mirror fails loudly.

Hard: first run is ~1.08 GB; broad-coverage locales (for example hu, cs, et) may
still miss the WER gate and must ship `simplify_only`; the int8 conversion and
its license obligations belong to the NVIDIA Open Model License (OpenMDW v1.1),
not to sherpa's Apache-2.0 tooling; the GGUF's prompt contract is exact and the
current click path passes rolling context, which must be removed or the model
degrades silently; 560 ms is a fixed export, so changing the chunk is a model
version bump.

## Revisit when

A locale misses the WER gate even after a fixture review, CPU RTF on tier C
exceeds 0.5, or a newer Nemotron checkpoint/fine-tune lands. Any change updates
this ADR, the catalog hashes, and `docs/qa/2026-11-22-model-pins.md`.
