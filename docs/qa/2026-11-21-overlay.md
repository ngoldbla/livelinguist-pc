## Linux dev result

`transport.setWindowMode("overlay")` returned:

```json
{
  "applied": true,
  "backend": "x11",
  "notes": [
    "above=true", "skip_taskbar=true", "sticky=true",
    "window_type=utility", "user_time=0",
    "input=false, WM_TAKE_FOCUS removed", "borderless"
  ]
}
```

`xprop -id <window>` confirmed:

```
_NET_WM_STATE(ATOM) = _NET_WM_STATE_SKIP_PAGER, _NET_WM_STATE_SKIP_TASKBAR,
                      _NET_WM_STATE_ABOVE, _NET_WM_STATE_STICKY, _NET_WM_STATE_FOCUSED
_NET_WM_WINDOW_TYPE(ATOM) = _NET_WM_WINDOW_TYPE_UTILITY
_NET_WM_DESKTOP(CARDINAL) = 4294967295
WM_HINTS: Client accepts input or input focus: False
_MOTIF_WM_HINTS(_MOTIF_WM_HINTS) = 0x2, 0x0, 0x1, 0x0, 0x0
```

The 780×250 overlay screenshot (`docs/screenshots/m2/overlay.png`) is
borderless. Discovery uses `_NET_CLIENT_LIST` + `_NET_WM_PID` + a title nonce
(the process id), never the title alone.

```bash
cargo test -p ll-window

# applies overlay hints, reads back utility type and all-desktop value
```

## Windows

`core/crates/ll-window/src/win32.rs` implements:

- `SetWindowPos(HWND_TOPMOST/HWND_NOTOPMOST)`
- `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` toggling
- `SetWindowSubclass` + `WM_MOUSEACTIVATE -> MA_NOACTIVATE`
- DWM rounded-corner attribute
- `ReleaseCapture` + `WM_NCLBUTTONDOWN/HTCAPTION` drag
- HWND discovery by process id + title nonce

Verified on Linux by target checking (not executing):

```bash
cargo check -p ll-window --target x86_64-pc-windows-msvc   # pass
```

The plan's required real-window acceptance (topmost over full-screen video,
focus retention while typing elsewhere, unfocused click/hover, drag, 100/125/150%
DPI, multi-monitor) must run on the Windows side of the dual boot. It is
**not claimed** here.
