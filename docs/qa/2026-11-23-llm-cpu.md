# Simplifier on CPU: llama.cpp evidence (S5: T17–T22)

Linux dev container (4 logical CPUs, 15 GB RAM), 2026-11-24. **Every latency,
TTFT, tok/s, p95 and RSS number here is a Linux 4-core approximation, not the
Windows tier C gate.** No caption or model output text is recorded.

## Probe

- Crate: `llama-cpp-2` =0.1.161, `default-features = false, features = ["openmp"]`, CPU only (no `cuda`,
  `vulkan`, `dynamic-backends`). llama.cpp is compiled from the crate's
  vendored sources (cmake). The MSVC build is proven by the windows-latest CI
  job. With the default features, llama.cpp's `common` library
  (`std::regex` statics) was linked into the same binary as sherpa-onnx's
  prebuilt static libs. Debug test binaries with both features then aborted
  at startup (`std::bad_alloc` in a static `std::regex` constructor; a C++
  one-definition clash between the two libraries' template instances).
  Without `common` (as the T17 card's fallback says) both features link
  cleanly. The core library still clashes on Linux: a release binary with both
  features aborts creating the ASR recognizer, so sherpa-onnx links shared on
  Linux (ADR 0022, 2026-11-24). The numbers below are unchanged (10-click re-check: p95 1,875 ms,
  RSS 895 MB).
- Model: `Qwen3-0.6B-EasyLanguage-Q4_K_M.gguf` (pinned, SHA-256 verified),
  mmap on, mlock off, `n_ctx` 2048.
- Prompt: `render_easylanguage_prompt` (T09) for en-US with the card's fixed
  sentence. Sampling follows the model card: greedy, repeat penalty 1.3 over
  the last 20 tokens, at most 128 new tokens. llama.cpp logs are silenced
  (`void_logs`), so no prompt text reaches stderr.
- `cargo run --release -p ll-llm --features llama --example llama_probe -- <gguf> en-US`
  (3 threads): load **390 ms**, prompt 286 tokens, **TTFT 1,146 ms**, 18
  tokens generated at **34.3 tok/s**, **total 1,671 ms**. No `<think>` text is
  left after `strip_think_block`.
- Same language: **yes** (plain English, shorter than the input; checked by eye
  at the terminal, and the `simplifies_en_sentence` test passes the English
  language guard).

## Backend (T18)

`ll_llm::LlamaBackend::load(gguf, threads)`. A missing file gives
`LLM model missing: <file>`, which `is_model_missing` recognizes. It creates
one llama context per call: no `unsafe`, because the context borrows the
model. That cost is inside the click times below. The generation stops at
end-of-generation, at `min(128, 3 × sentence tokens + 32)` new tokens (the
card's `n_predict` 128 caps the T18 card's 256), or after 15 s (`timeout`).
Only `request.sentence` is used.

The click path for the fine-tuned model uses
`SimplifyConfig::on_demand_fine_tuned()`: no retries, because the prompt is
fixed and decoding is greedy, so a retry would repeat the same text.
Validators and the verbatim fallback still run.

## In app (T20)

- `ll-eval --features llama --scenario simplify-only --language en-US --llm llama --text "<card sentence>"`:
  1 segment, simplified (16 words).
- Bridge (`--features llama`): real sessions (system audio or a non-mock
  scenario) get a `LazyBackend` that loads the GGUF on the **first click**,
  never at start.
  - Missing model, normal scenario: the caption stays verbatim (≡) and an
    `LLM_MODEL_MISSING` error event drives the banner.
  - Strict scenario: the session stops with the error (rule 7).
  - The policy (`ll_llm::click_failure`) and the lazy loading are unit-tested
    with mock loaders.
- **Windows pending:** build the bridge with `--features capture,sherpa,llama`,
  caption an English video, click a sentence, and take the screenshot
  `console-click-simplified.png`.

## Tier C

`ll-eval --scenario click-bench --clicks 50 --language en-US --llm llama --threads N`.
It finalizes 50 demo segments and clicks each through `Pipeline::simplify_now`
(the UI path), timing click → simplified result.

- Tier C approximation on Linux: `taskset -c 0-3 nice -n 10`.
- Peak RSS: `VmHWM` of the process.
- `scripts/tier-c-profile.ps1` (affinity 0xF, BelowNormal, PeakWorkingSet64)
  is written for Windows and **not run here**.

## 29-pack matrix

`ll-eval --features llama --scenario simplify-matrix --llm llama --threads 3`
(`taskset -c 0-3`). For every locale it takes the pack's first 2 demo
sentences, simplifies each **twice** with `LlamaBackend`, then applies the
language guard and the pack's validators. It also runs once more **without**
the ` /no_think` soft switch: the A/B for the open prompt-contract item (see
`docs/qa/2026-11-23-easylanguage-prompt-contract.md`).

Gate per locale: `ran`, `deterministic`, and same language 2/2.

Result: **28/29 pass. es-ES fails same language 1/2.** Its outputs were
checked by eye, locally (they are not committed): both are Spanish. The
language guard (stopword overlap) misclassified one short Spanish output.
This is a false negative, not a translation. The pack and the prompt are
unchanged, as the card requires. A human decides whether this blocks S5.

Totals:
- Same language 57/58; deterministic 29/29 locales.
- 4 outputs have a hard validator violation (shown flagged); 0 verbatim.
- p95 over all 174 generations: 4,602 ms. Peak RSS 906 MB.
- A/B without ` /no_think`: same language 57/58. 23/58 outputs are identical
  to the with-switch output. Neither variant is better on these counts.
- All timings: Linux 4-core approximation, not the Windows tier C gate.
