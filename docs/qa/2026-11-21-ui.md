## Accessibility / keyboard

- All interactive elements use `role`, `aria-label`, `tabIndex`, and Enter/Space
  handlers where GPUIX supports them.
- Caption rows are buttons with sentence + action labels; Enter/Space
  simplifies.
- Sliders expose `role="slider"`, `aria-valuetext`, arrow keys.
- Visible focus uses `focusVisible` outlines.
- Caption announcements: GPUIX 0.11 has no live-region API (Q-010/Q-013); the
  expanded view provides a **Read latest** action until upstream support lands.
- Keyboard paths are guaranteed in console/expanded; overlay is pointer-first
  by design (D-046).

## i18n

- 29 locale catalogs in `assets/locales`, converted from the Mac
  `Localizable.xcstrings` (124 translated keys) plus desktop keys, 274 keys total.
- Resolution: explicit learning language (immersive mode) -> device -> English;
  base-code fallback.
- Arabic catalog and `isRtl` are tested; Noto Sans Arabic is registered at
  startup. Full row mirroring is a follow-up because GPUIX lacks a direction
  primitive; text alignment and RTL detection are in place.

## Visual checks

Screenshots are real GPU-rendered windows captured with ImageMagick
`import -window` (GPUIX 0.11 has no Linux PNG test renderer). The overlay is
verified borderless/topmost through X11; see `2026-11-21-overlay.md`.

## Known limits

- No real ASR/GGUF models are installed. The demo conversation and typed input
  run the real pipeline/engine; the UI labels ASR `simplify only` rather than
  faking listening.
- Windows UI/D3D/WASAPI acceptance is pending the Windows side of the dual boot.
