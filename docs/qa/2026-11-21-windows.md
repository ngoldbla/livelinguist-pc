# Windows target evidence

- Date: 2026-11-21
- Status: cross-target compile **pass**; real Windows 11 acceptance **pending**.

## What is verified from Linux

```bash
rustup target add x86_64-pc-windows-msvc
cargo check -p ll-window --target x86_64-pc-windows-msvc
# Finished: ll-window compiles for Windows x64
```

This compiles the raw-FFI Win32 policy in `core/crates/ll-window/src/win32.rs`:
topmost, no-activate extended styles, `SetWindowSubclass`/`WM_MOUSEACTIVATE`,
DWM corner preference, drag, process+nonce window discovery.

The GitHub CI matrix also builds and tests the Rust workspace on
`windows-latest`, and builds the napi addon there.

## What is not verified

The plan's Windows release gate requires real hardware:

- Win32 overlay over full-screen video/call; focus retention while typing in
  another app; unfocused click/hover; drag; 100/125/150% DPI; multi-monitor.
- WASAPI microphone + loopback with a real call/video; 30-minute soak with
  xrun/overrun = 0 at tier C.
- D3D11/12 GPUIX UI, not Vulkan/lavapipe.
- NSIS install/upgrade/uninstall on a clean Windows 11 23H2+ install and the
  dual-boot Windows side.
- NVIDIA/AMD/Intel Vulkan and optional CUDA pack detection.
- Real Nemotron/Qwen3 model runs and product latency numbers.

Run the Windows side of the dual boot, execute `scripts/build-windows.ps1`, and
record results in `2026-11-21-packaging.md`, `2026-11-21-overlay.md`,
`2026-11-21-audio.md`, and `2026-11-21-llm-backends.md`. These remain outstanding
work, not passing checks.
