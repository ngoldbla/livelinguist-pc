# Code signing policy

Live Linguist PC is free, open-source software (MIT, see `LICENSE`). Its Windows
builds are signed through the SignPath Foundation's free program for open-source
projects.

**Free code signing provided by [SignPath.io](https://signpath.io), certificate
by [SignPath Foundation](https://signpath.org).**

The certificate is issued to SignPath Foundation, so **SignPath Foundation** is
the publisher shown by Windows, not an individual maintainer. The private key
never leaves SignPath's hardware security module, and SignPath verifies that
each signed file came from an automated build of this repository.

## What gets signed

Only binaries built from this repository's source by
[`.github/workflows/release.yml`](.github/workflows/release.yml) on
GitHub-hosted runners, from a `v*` release tag, and only after a maintainer
approves the signing request in SignPath.

| File | Signed | Notes |
| --- | --- | --- |
| `livelinguist.exe` | Yes | Application, used by both the installer and the portable ZIP |
| `livelinguist-core.node` | Yes | Rust core addon built from `core/crates/ll-bridge` |
| `LiveLinguist-<version>-setup.exe` | Yes | NSIS installer, signed after packaging |
| `uninstall.exe` | No | Generated by NSIS at install time; it cannot be signed by this pipeline |
| `gpuix-native.win32-x64-msvc.node` | No | Third-party GPUIX 0.11.0 runtime, Apache-2.0, redistributed unchanged |
| Downloaded models | No | Not part of any signed artifact; fetched separately, after the user asks |

Third-party binaries keep their upstream signatures and are never re-signed
with this project's certificate.

The portable ZIP is a plain archive of the signed payload. ZIP archives carry
no Authenticode signature; verify the files inside it.

## Who signs, and how a release is approved

| Role | Members |
| --- | --- |
| Authors (commit access) | [@ngoldbla](https://github.com/ngoldbla) |
| Reviewers (approve outside contributions) | [@ngoldbla](https://github.com/ngoldbla) |
| Approvers (approve each signing request) | [@ngoldbla](https://github.com/ngoldbla) |

Every team member uses multi-factor authentication for GitHub and SignPath.

- Changes from anyone without commit access arrive as pull requests and are
  reviewed before merge.
- Control of release tags and of the SignPath configuration stays with the
  approver above.
- CI can submit a signing request but cannot approve one. A maintainer approves
  each request in SignPath after checking the source commit, the workflow run
  and the artifacts. Signing does not publish anything; the maintainer
  publishes the release separately.
- Nothing is signed on a developer machine, and no certificate, key or token
  is stored in this repository.

## Privacy

Live Linguist processes audio and captions entirely on the user's PC. Audio,
captions and transcripts are never uploaded, logged or shared.

The only network activity is what the user explicitly starts:

- **Model download.** On first run the app offers a one-time download of the
  speech and simplification models (about 1.1 GB) from Hugging Face. Nothing is
  sent except the download request; it happens only when the user clicks
  **Download**.
- **Update check.** Opt-in and off by default. When enabled, it fetches the
  release list from GitHub. Nothing about the user or the session is sent.

No analytics, telemetry, crash reporting or usage data are collected. See the
privacy section of [README.md](README.md#privacy) for the user-facing statement.

## Verify a download

```powershell
Get-AuthenticodeSignature .\LiveLinguist-<version>-setup.exe |
  Format-List Status, SignerCertificate
```

`Status` must be `Valid` and the signer subject must contain
`CN=SignPath Foundation`. Then compare `Get-FileHash` against the
`SHA256SUMS.txt` attached to the release, and optionally check the build
provenance: `gh attestation verify <file> --repo ngoldbla/livelinguist-pc`.

Builds published before the project was accepted into the program are unsigned,
and the release notes of those builds say so.

## Report a problem

A signature that does not verify, or a binary that does not match this
repository's source, is a security issue: see [SECURITY.md](SECURITY.md). Do not
open a public issue for it.
